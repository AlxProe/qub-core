Already have QUB Core?

Install over your existing mainnet installation. No uninstall is needed.

App closes but stays on 1.8.4? If the old updater closes QUB Core without installing or restarting, use the installer above and follow these steps.

  1. Stop mining and close Core

    Stop solo or pool mining, then fully exit QUB Core before running the installer. Keep a safe backup of your wallet.

  2. Run the downloaded installer

    Use your existing Qubit Coin Core installation folder. The installer updates program files and keeps your existing wallet, chain data, and settings.

  3. Open Core and check 1.8.7

    Open QUB Core from your usual shortcut and confirm version 1.8.7. Let synchronization finish before starting solo or pool mining.

Do not delete your data folder to upgrade. If you still see 1.8.4, check that the installer and shortcut point to the same installation folder.

QUB, JIN and the wider ecosystem

Mine QUB and use native JIN on the Qubit blockchain. The planned Enjin bridge is a separate part of the roadmap.

QUB is what you mine

Miners secure the network and earn QUB block rewards. Core supports solo and pool mining, with CPU and supported OpenCL GPUs.

JIN is native to Core

View and send native JIN in your QUB wallet. Infuse JIN into the QUB reserve or melt QUB to reclaim JIN using the app’s built-in actions and current conversion quote.

Enjin is on the roadmap

A 1:1 bridge between JIN Coin on Qubit and JIN Token on Enjin Matrixchain is planned. That bridge is not available in this release.

JIN infused into QUB

Infuse and Melt are available on QUB mainnet. Use the app to review the current amounts before confirming a transaction.

1
Mine or receive QUB.

Use the wallet to hold and send QUB, or earn it through mining.

2
Infuse JIN.

The Infuse action adds native JIN to the QUB reserve.

3
Melt QUB.

The Melt action permanently destroys QUB and returns JIN according to the protocol’s current quote.

4
Follow the bridge roadmap.

Moving JIN between Qubit and Enjin Matrixchain requires the planned bridge, which is not live in 1.8.7.

Use the built-in Infuse and Melt actions. Sending coins directly to protocol addresses does not perform a conversion.

What’s new

The current release, followed by selected milestones from the early release history.

v1.8.7 · HF134 — Updater and sync reliability+
  • Windows updates: a separate helper verifies the installer, waits for Core to close, installs and relaunches. Preparation runs outside the GUI thread.
  • Synchronization: avoids replaying already known snapshots and reuses locally validated chain prefixes while checking replacement blocks normally.
  • Storage: adds writer progress diagnostics and coinbase UTXO optimizations. Exact Windows and Linux source variants are published with their provenance.
  • Compatibility: existing epoch-3 / ASERT-MTP rules from block 100000 remain unchanged. There is no new activation height.
  • Next patch: long-running memory behavior, seed-independent mining, and faster startup/recovery remain open work.

Read the complete HF134 release notes →

v1.8.6 · HF133 — Mainnet upgrade+
  • Required before block 100000: all wallets, solo and pool miners, and node operators must upgrade. Activation is set by block height, not a calendar date.
  • New difficulty adjustment: ASERT-MTP activates at block 100000, with a 60-second target. It is designed to reduce repeated difficulty swings as mining power changes; individual block times will still vary.
  • Sync and memory improvements: bounds incoming chain synchronization, releases old connection snapshots, and avoids redundant history replay and large message copies.
  • GPU mining, reward amounts, pool rules, QNS/JIN rules, and the existing chain data format retain their behavior.
  • Older releases, including 1.8.4, cannot follow the upgraded chain after activation. Do not downgrade after activation.
